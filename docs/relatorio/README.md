## Regras

- Cada parte começa pela conclusão principal, e só depois os detalhes.
- Os requisitos são citados pelo ID (RF-xx, RNF-xx, A-xx), como na especificação da M1.
- Os números (tempos, contagens, percentagens) vêm de dados reais: `metricas/`, o histórico do GitHub Actions, os testes. Nunca estimados.
- As alterações ao relatório entram por pull request, como o código.
